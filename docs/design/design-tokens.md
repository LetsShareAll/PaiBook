# 设计 token 推导记录

这份文件存在的唯一理由：把**重建**和**临摹**在事后区分开。ADR-0007 的防线是不临摹——"自绘"不构成抗辩，拆解设计语言后重建才构成。但那是个过程，没有自动化手段能校验，只能靠记录。这里是唯一被允许保存的"参照物残留"，而且只保存文字。

## 规则

1. 每条取值记四件事：**它表达哪个可观察的官方特征**、**与那个特征的关系**（一致 / 部分一致 / 无对应物）、**为什么是它而不是邻近的值**、**数值本身是怎么来的**（重建 / 照抄 / 不可追认）。
2. **写不出依据的值，就是照抄来的。** 第 1 项填不出来的取值应当重做或替换，而不是补一段听起来合理的说明。
3. 只记设计语言层面的量（配色取向、字阶关系、圆角尺度、动效曲线、信息密度），不记坐标、尺寸、像素比这类可以反向还原界面的数据。
4. 参照物本身不入仓库（见 ADR-0007）。要看官方界面就去看，看完只往这里写字。

## 记录格式

| token | 表达的设计语言 | 取值 | 与特征的关系 | 数值来源 |

## 参照观察（2026-10-06）

来源：三个游戏的官方网站。快照存在被 gitignore 的 `browser-screenshots/`，不入仓库。

**观察范围有限**：只看了官网的首页与资讯页共五六个页面，**没有观察游戏内界面**。游戏内界面是另一个来源，本次未核实——下面的每一条都只代表官网。

### 三个官方站点的共同点

- **都不加载 CJK webfont，都用系统字体栈。** 原神站是 `Microsoft YaHei / 微软雅黑 / STHeiti / MingLiu`，星铁与绝区零是 `Helvetica neue / PingFang SC / Hiragino Sans GB / Microsoft YaHei UI / Microsoft YaHei / Arial`。这是 ADR-0007 字体策略的直接旁证。
- 信息层都浮在**全幅插画**之上，用半透明或实心面板划出阅读区。

### 原神

- 载入画面：暖羊皮纸静物插画（书籍、卷轴、鹅毛笔、放大镜），暖棕色调 + 深色暗角。
- 首页：全幅插画背景 + **深色半透明面板**承载资讯；白字；选项卡激活态是**暖金色下划线**；区块标题白色大字号，两侧是 ✦ 菱形纹饰。
- 资讯详情页：**深蓝星空背景 + 近中性浅色的正文面板**；标题在浅面板上是深灰大字、宽字距；面包屑在暗色层上。
- 一句话：**暗色外壳 + 浅色阅读面板 + 暖金强调。**

### 星铁

- 全幅主视觉：深蓝 / 青绿、星云、金色华丽边框纹样。
- 按钮：圆角矩形 + 半透明深蓝填充 + 细描边；下载按钮是胶囊形 + 金色 / 玫瑰色描边与辉光。
- 一句话：**深空蓝底 + 圆角 + 内发光描边 + 星点。**

### 绝区零

- 全幅主视觉上下黑边（电影化）；散布小方块「■」标记。
- 按钮：**斜切 / 角形的红黑告示板**，硬边、白描边、零圆角；标题紧凑、高字重、负字距。
- 一句话：**近黑底 + 硬边直角 + 高字重标题 + 告示板式强调块。**

## 结论

1. **没有发现凭空捏造的取值**——三站的取值都能与各自游戏的可观察设计语言对上，或者属于"排版通识"（行宽、间距阶）。
2. **但没有任何一条能证明"为什么恰好是这个数值"。** 当初没留下记录，事后无法追认：说清"它属于哪个设计语言"并不能证明它不是从截图上吸色得来的。按规则，这一栏如实标为**不可追认**，而不是补一段听起来合理的说明。本文件从建立的第一天起就带着这个缺口，这是事实，不是待办。
3. 因此本文件的效力**面向未来**：从下一次改动起，每个值都必须留下可核对的依据；旧值在被替换之前保持不动，也不得据"看起来还行"去调整。
4. 唯一的实质发现是**原神站的结构缺口**：官方的阅读体验是"暗色外壳 + 浅色阅读面板 + 暖金强调"，我们是通体浅色。**色相不是问题，结构是。** 这是将来决定要不要重做原神站时，唯一值得依据的事实。

## 下一步

- 原神站：把"暗色外壳 + 浅色阅读面板"记为待评估的改法，**不在此处决定**。
- 星铁站、绝区零站：没有发现结构性问题。两处"部分一致"（星铁的强调色、绝区零的强调色）需要补充来源——要么补上游戏内界面的观察，要么在下次改动时按第 3 条重新推导。
