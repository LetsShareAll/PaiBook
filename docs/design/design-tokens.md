# 设计 token 推导记录

这份文件存在的唯一理由：把**重建**和**临摹**在事后区分开。ADR-0007 的防线是不临摹——"自绘"不构成抗辩，拆解设计语言后重建才构成。但那是个过程，没有自动化手段能校验，只能靠记录。这里是唯一被允许保存的"参照物残留"，而且只保存文字。

## 规则

1. 每条设计语言取值记三件事：**它表达哪个可观察的官方特征**、**为什么是它而不是邻近的值**、**这个值是我们重建的还是照抄的**。
2. **写不出依据的值，就是照抄来的。** 第 1 项填不出来的取值，说明它的来源是某张截图上的吸色或对视，应当重做或替换，而不是补一段听起来合理的说明。
3. 只记设计语言层面的量（配色取向、字阶关系、圆角尺度、动效曲线、信息密度），不记坐标、尺寸、像素比这类可以反向还原界面的数据。
4. 参照物本身不入仓库（见 ADR-0007）。要看官方界面就去看，看完只往这里写字。

## 记录格式

| token | 表达的设计语言 | 取值 | 为什么是这个值 | 来源 |

### 设计语言取值：依据缺失

三个站的配色、圆角、描边、阴影、背景层取值，目前**没有任何可追溯的推导记录**——它们写进 `tokens.css` 时没有留下依据。这不是待补的小事，它意味着我们**无法判断这些值当初是拆解设计语言后的重建，还是对着截图吸色/临摹的产物**，因此也无法判断它们是否落在 ADR-0007 的合格侧。

在补齐之前，**不要基于"它们看起来还行"去调整它们**——在没有依据的前提下改动，只会把可追溯性推得更远。

补记录的标准只有一条：能不能写出"这个值表达官方的哪个可观察特征，以及为什么是它而不是邻近的值"。写不出来的，替换掉。
