# 不使用官方美术素材与游戏内字体

站点复刻游戏 UI 的**设计语言**——配色、字阶、圆角尺度、动效曲线、信息密度、面板与按钮的形态手感——但所有图标、纹样、背景一律自绘，绝不使用官方 logo、立绘或 UI 截图；绝不打包或自托管游戏内字体文件。配合页脚常驻的非官方声明与米哈游要求的署名声明，以及"完全免费"承诺（无广告、无打赏、无会员）。

**防线是不临摹，不是自绘。** 自绘只解决素材来源，不解决方法：自绘一张和官方界面一模一样的图，依然是描改。原神指引明确禁止"【描改】、【局部改动】官方素材"，绝区零指引要求"二次独创…务必不要直接使用或描改官方素材"。所以合规与否由**过程**决定：

- 拆解官方界面的设计语言（取色、字阶、圆角尺度、动效曲线、信息密度）后，用我们自己的构件从零重建；
- **不对着官方截图逐屏临摹**，不做像素级对齐。

判据：把我们的页面和对应官方页面并排——玩家说"这是一套设计语言下的另一个产品"合格；说"这是同一个应用"越线。

理由：三份官方同人指引都没有授权把官方素材放上网站，星铁指引还明确排除纯搬运，并自认其声明"不构成法律意义上的许可"——官方容忍不等于授权。官方自己的站点能自托管游戏字体、能直接用官方美术，是因为他们有权；他们发出来的文件不因此变成我们可以使用的素材。

## 参照物不入仓库

官方 UI 截图与第三方页面快照里含官方美术，而仓库公开，commit 等于公开再分发。这类快照只存被 gitignore 的目录（`.screenshots/`、`browser-screenshots/`），仓库里只保留从中提取出的文字规范与自绘资产。设计 token 的推导记录见 `docs/design/design-tokens.md`。

## 字体策略（实测订正）

最初接 `@nuxt/fonts`（Google Fonts 的 Noto Sans/Serif SC），但它在这套配置下只生成空 CSS——页面实际用的是系统字体，等于留了个"看起来配好、其实没生效"的陷阱。已移除该模块，改为：

- 正文走系统 CJK 字体栈（`PingFang SC` / `Hiragino Sans GB` / `Microsoft YaHei` / `system-ui`），标题另加 `Songti SC` / `SimSun` 等衬线兜底。token 里不写任何既不打包、也不在系统栈里的字体名。
- **不打包任何 webfont**：CJK webfont 动辄数 MB，对攻略站不值得。
- **游戏内字体文件不能用**（2026-10 核实）：原神、星铁、绝区零的中文 UI 字体分别是**汉仪文黑 85W**、**汉仪旗黑 65**、**印品鸿蒙体**，全是第三方商业字库，没有一款是开源字体。汉仪的免费个人非商用许可明确禁止"将字体加载、显示到您或第三方经营的产品或服务本身中"及用于网页设计（`hanyi.com.cn/user-doc-1` 第 2.2.4 条）——**即便非商业也拿不到许可**；而自托管是把字体软件文件分发给所有人，性质比"用字形"更明确。字库作为计算机软件受保护已到最高法层级（[2010]民三终字第6号，方正诉暴雪）。
- 将来若确要统一观感，再自托管 OFL / 免费商用子集字体（星铁观感最接近的是与汉仪旗黑同源的 HarmonyOS Sans，绝区零是得意黑 OFL，原神是思源黑体 / MiSans）——那仍是一次独立的、有明确收益的决定，且动手前要先核实各字体的许可是否允许 webfont 嵌入（免费 ≠ 允许嵌入）。

## Consequences

- "复刻设计语言、不复制界面"比"自绘"严格：它约束的是过程而不是产出，因此无法用自动化校验，只能靠并排判据人工过。
- 三个站点的视觉差异靠 token 与自绘资产拉开，这会显著增加设计工作量。这是刻意的代价。
- 因为承诺非商业，引用 CC BY-NC-SA 来源的内容才成立；一旦要变现，必须先回头处理这件事（从站外拿什么，见 ADR-0009）。
- 字体在不同操作系统上会略有差异（这是显式接受的代价，不是疏漏）。
