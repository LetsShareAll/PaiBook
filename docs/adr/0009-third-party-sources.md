# 第三方来源：参考与引用分开对待

站点需要外部参照，但"学它怎么组织信息"和"搬它的东西"是两件事，受完全不同的约束。**参考**不受许可约束——信息架构、交互结构、问题清单不构成受保护的作品；**引用**受，而且每一层的风险完全不同。

bwiki（`wiki.biligame.com/ys` `/sr` `/zzz`）值得参考的是"社区 wiki 怎么让玩家快速找到答案"这件事已经解决过的版本；**不值得参考的是它的观感**——那个"像官方"的界面里叠着 bwiki 美术和米哈游美术两层，照它做等于绕道使用官方素材。

素材与字体的红线见 ADR-0007，本条只管"从站外拿什么"。

## 参考：可以借鉴什么

- 信息架构与内容组织：条目怎么分、一篇攻略该回答哪些问题。
- 交互结构：信息层级、点击路径、动效节奏、组件行为。这些没有品牌识别功能，复刻它们不会造成误认。
- **不参考它的视觉外观**：只复刻设计语言，不复制界面，不逐屏临摹官方截图。判据见 ADR-0007。
- **参照物不入仓库**：官方 UI 截图、bwiki 页面快照存在被 gitignore 的目录（`.screenshots/`、`browser-screenshots/`），仓库只保留从中提取出的文字规范与自绘资产。仓库公开，commit 快照等于公开再分发。
- **只看，不抓**：不写爬虫、不碰 `api.php`。bwiki 的 `robots.txt` 没有禁止 `api.php`，但它没有任何抓取/API 政策，而页脚那份用户协议禁止"复制…传播和陈列…图文音像资料的全部或部分内容——无论是营利的还是非营利的"。未被 robots 禁止不等于被授权，批量抓取正是那条协议的字面情形。

## 引用：许可实况与可用范围

**bwiki 的页脚声明背后没有一份可援引的内容许可文件。** 2026-10 实测：

- 页脚锚点指向 `creativecommons.org/licenses/by-nc-sa/4.0/`（是 **4.0**，不是常被误传的 3.0），正文另称"若无特殊说明，wiki 内容按 CC BY-NC-SA 协议提供"。
- MediaWiki API 的机器可读许可为空：`api.php?action=query&meta=siteinfo&siprop=rightsinfo` → `"url":"","text":""`。
- 各站《免责声明》只谈准确性与责任豁免，完全不提 CC 与转载授权。
- 页脚"用户协议"指向《哔哩哔哩游戏中心用户协议》，其"本平台服务"定义为游戏下载/预约/测试/跳转/登录/支付，**全文未提 WIKI 内容**——它不是 wiki 的内容许可。

许可的适用面因此是模糊的，而"若无特殊说明"那半句把转载内容排除在外：bwiki 的攻略正文有相当一部分转自米游社、NGA 与官方公告，那部分版权仍在原作者手里，不归 bwiki 的声明管。

**可用范围**（比许可本身更严）：

- **数值事实**可以用（角色属性、材料、版本号这类游戏事实），但必须自行重建数据结构、自行撰写文案；**排版、表格结构、文案、摘要一概不搬**。
- 溯源优先级：**游戏内文本 / 官方公告 > 官方账号（米游社官方号、HoYoLAB 官方）> 社区 wiki（bwiki）> 第三方攻略**。任何进站的数值必须能追到前两级；追不到就标为待证实或不收。bwiki 只在"帮我快速定位问题"这一层有用。
- 攻略正文走 `Link`，只存标题、自写摘要、作者与来源、URL，站内不承载正文（见 `CONTEXT.md`）。
- **米哈游给的是容忍，不是许可**：星铁指引 V3.0 原话是"不能视为法律意义上的许可及/或授权（含默示许可）"。页脚常驻三段——非官方声明、"游戏名称与角色名称等权利归米哈游所有"、完全免费无变现承诺；且**不得暗示或声明得到米哈游赞助、认可或批准**。
- 记录粒度到 `Guide`：来源与核实日期进元数据，不上前台，也不细到字段（细到字段没人维护，最后一定烂掉）。

## 绝区零的缺口

三个站不是同一条基线，有两处缺口只落在绝区零：

- **指引缺口**：星铁 V3.0 明文"不禁止非商业性质的个人使用"，原神指引有"仅可作同好交流学习之用"，**绝区零只有"二次独创、务必不要直接使用或描改官方素材"的禁令，没有对应的容忍专条**。这一站缺少那层背书，不能从另两站外推。
- **数据源缺口**：`scripts/import-entities.mjs` 的来源是 genshin-db（MIT）与 Mar-7th/StarRailRes，脚本里写着"绝区零：暂无许可清晰的公开数据源，留待补"。它的实体数据只能手工维护。

规则仍按三站统一执行（不为绝区零单开一套），但这两处缺口记录在案：绝区零站没有兜底。

## Considered Options

- 直接以 bwiki 的页脚声明为据引用内容：它的声明背后没有许可文件，"若无特殊说明"还把转载内容排除在外，出了事无从追溯。
- 完全不用任何外部参考：可行，但等于重新发现"社区 wiki 该怎么组织信息"这件已经被解决过的事。
- 按站分级保守度：规则本应跟着最弱的那条链走，但三站分叉会让规范与实现都复杂一倍，收益不抵。
- 抓 `api.php` 批量取数：省一次人工，代价是把"看几页"变成"建镜像"，正好落在页脚协议的字面禁区里。

## Consequences

- bwiki 的观感是首要放弃项，"像不像那个游戏"只能靠自绘资产与 token 调，成本落在设计上。
- 数值要人工复核到官方文本，比抄一份表慢得多。这是刻意的代价。
- 非商业现在是**别人内容的许可条件**，不再只是本站对自己的承诺。一旦要变现，bwiki 来源的一切都得先拆掉——这是 ADR-0007 里那句"必须先回头处理这件事"的具体含义。
