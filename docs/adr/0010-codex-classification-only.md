# 图鉴只放分类，不放数值

每个 Game 带一份角色图鉴：列表按元素 / 职业 / 稀有度 / 阵营筛选，条目页是这个角色的攻略与站外推荐。**图鉴里只有分类元数据，没有任何数值**——没有攻击力、没有倍率、没有成长曲线。

理由：数值必须能追到游戏内文本或官方公告（ADR-0009），而现在唯一现成的数据源是社区数据集（genshin-db、Mar-7th/StarRailRes，都是 MIT），按那条规则排在第三档，进不了站。分类不一样——稀有度、元素、命途、所属是**结构性事实**，玩家拿它筛选，错了也只是筛错；数值错了就是误导。

代价是图鉴比玩家预期的薄。这是刻意的：宁可薄，也不要一个会过期的数字。版本一更新，数值必然失效；攻略只要标"适用版本"就完事，图鉴却要维护一整套版本对应关系——那是持续的人力，不是一次性工作。

## 分类词表

三款游戏的分类词表不一样（原神是元素 + 武器类型 + 地区，星铁是属性 + 命途，绝区零是属性 + 定位），所以统一收进四个键，存成一列 JSON：

`element` 元素 / 属性 · `class` 职业（武器类型 / 命途 / 定位） · `rarity` 稀有度 · `faction` 阵营 / 所属

页面不维护词表：有哪些键、每个键有哪些取值、各多少个，都由数据推出来。

## 数据来源

- **原神**：genshin-db（MIT）—— `elementText` / `weaponText` / `rarity` / `region`
- **星铁**：Mar-7th/StarRailRes（MIT）—— 角色表 + 命途 / 属性词表
- **绝区零**：**没有干净的数据源**。官方角色页（`zzz.mihoyo.com/character`）有名单、英文名与所属，但没有稀有度 / 属性 / 定位；这部分在写作台的「分类维护」手工录。

**不从 bwiki 抓**：它的页脚声明背后没有可援引的内容许可文件（见 ADR-0009），而且社区 wiki 的准确性并不比别处高。

## Consequences

- 图鉴的价值在"把攻略挂到人身上"和"按分类找得到"，不在"查数据"。想查数值的人会去别处，这一点是接受的。
- 将来若要补数值，得先有一条达到 ADR-0009 那条线的数据源，或者先改 0009。这个口子留着，但不要在没有源的时候偷偷放宽。
- 同名不同形态的角色（三月七 / 三月七·巡猎、开拓者 ×10）在导入时按 `class` 拆名，否则会撞 `(game_id, kind, name_zh)` 的唯一索引被整行丢掉。拆出来的名字是玩家实际在用的叫法。
- 图鉴收录的是"被攻略引用到的实体"加上导入的名单，不是全量收录——`CONTEXT.md` 里 Entity 那条仍然有效。
